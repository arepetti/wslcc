# Governance

WSLCC is a single-maintainer, spare-time open-source project. This document sets expectations so contributors know how decisions are made.

## Roles

- **Maintainer** — currently a single person (the project author). Has final say on scope, design, releases, and what gets merged.
- **Contributors** — anyone who opens issues or pull requests. Very welcome, subject to review.

## Decision making

- Decisions are made by the maintainer, informed by discussion in issues and pull requests.
- There is no formal voting process. When in doubt, open an issue to discuss before investing in a large change.

## Scope

- The project aims to provide a `docker compose`-style experience for WSL containers, with a unified interface across providers. Features outside that scope may be declined to keep the project maintainable.

## Expectations and cadence

- This is spare-time work: reviews, responses, and releases are best-effort with no SLA.
- Breaking changes are expected while the project is pre-1.0 and are recorded in [CHANGELOG.md](CHANGELOG.md).

## Continuity

- If maintenance stops, the MIT license permits forking. The project may add additional maintainers over time if sustained, high-quality contributions warrant it.
